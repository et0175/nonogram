Source: docs/monogram_analyzer.md points 1-3, 2026-08-30.
- Track branching/ambiguity during solving: average and maximum per-line candidate-pattern counts at each propagation fixpoint, plus an approximate remaining-configuration-count curve (a cheap proxy — the product of per-line candidate counts — not an exact count, which is combinatorially infeasible) (FR). Source: docs/monogram_analyzer.md points 4 and 6, 2026-08-30.
- Report information gain per deduction: number of cells determined by each individual logical step, and the average cells-determined-per-deduction across the whole puzzle (FR). Source: docs/monogram_analyzer.md point 5, 2026-08-30.
- Run a separate, non-fail-fast search pass (distinct from the generation-time uniqueness check, which must keep exiting early) to record backtracking/search statistics: number of branch points, maximum branch depth, number of contradictions, number of states explored (FR). Source: docs/monogram_analyzer.md point 7, 2026-08-30.
- Detect dependency depth (the longest chain of deductions where each one enables the next) and bottlenecks (stall points where progress halts until one specific deduction unlocks a large portion of the grid), reporting count/size/depth/cells-unlocked per bottleneck (FR). Source: docs/monogram_analyzer.md points 9-10, 2026-08-30.
- Report clue-density statistics for a puzzle: filled/empty cell counts, clue count, average clue length, maximum clue length, and overall clue density (FR). Source: docs/monogram_analyzer.md point 11, 2026-08-30.

# processed: 2026-08-30 → NFR-004
- The local web UI must refuse a request that the browser itself marks as cross-site (`Sec-Fetch-Site` other than `same-origin`/`none`, or an `Origin` naming a non-loopback host), and must refuse an absolute-form request target whose authority is not a loopback name. Binding to 127.0.0.1 does NOT prevent this: a browser sets `Host` from the *target* URL, so a form on a malicious page submitting to 127.0.0.1 arrives with an allowlisted `Host` and is currently served. Verified on the wire against the merged CARD-019 code, 2026-08-30: cross-site GET -> 200, absolute-form target with no Host -> 200, foreign Host in origin-form -> 400 (the only case the current check covers). This is what makes BCON-0001's "never network-exposed" true for browser-mediated reach, not just for socket reach (NFR, security). Source: independent post-hoc review of CARD-019 (meta/review/20260830T163436Z-CARD-019-posthoc.yml, findings F-001/F-002), 2026-08-30.

# processed: 2026-08-31 → EC-007 (wording correction)
- AMENDS EC-007: its closing clause "refused before any conversion, dithering or solver work runs" is literally false on one path and must be narrowed to what the implementation can guarantee — "refused before any cropping, dithering or solver work runs". Loading and greyscaling are NOT refusal-free in general. Where a source's header extent and its decoded extent disagree, the refusal necessarily comes after `load_greyscale`, because the extent being judged is the one only the decode knows. Two disagreement classes measured on Pillow 12.3.0, CARD-026 review cycle 2, 2026-08-31: a PNG whose `eXIf` chunk follows `IDAT` (563x980 stored, 980x563 displayed — `Image.open` never reaches the chunk), and an orientation-tagged TIFF (60x40 + `tiffinfo={274: 6}` probes (40,60), decodes (60,40) — Pillow's TIFF reader applies the orientation at open and `ImageOps.exif_transpose` applies it a second time). The two-stage guard that creates this path is what makes CON-012 hold unconditionally: judging the header extent alone accepted a 15x30 request that retained only 0.287 of the displayed picture, a silent fail-OPEN. Cost of the narrowing, swept over all 441 grid shapes against the 563x980/980x563 disagreement: 105 accepted, 168 refused after the decode (the correct outcome), 168 false refusals — fail-CLOSED, each carrying an actionable message. Everything downstream of the decode (cropping, dithering, clue derivation, the solver) remains unreachable for every refused request, so the guarantee that matters is intact and only the word "conversion" was too broad (EC, correction). Source: meta/review/20260831T121656Z-CARD-026-cycle2.yml finding F-102, 2026-08-31.

- An uploaded picture is trimmed to its ink bounding box before it is fitted to the requested grid shape, so the finished grid carries at most one all-empty row or column at each edge (FR). Source: user request, 2026-09-01. Best-effort by explicit user decision, NOT a guaranteed invariant: trimming the source cannot guarantee the property on the grid, because the resize+dither step can still blank an edge row whose source content was faint. Measured over the 14 pictures in `pictures/`, 20x20, seed 1: 9 of 14 violate the rule today, worst `duck2.png` at 5 blank lines deep (257 of 400 cells, 64%, spent on border), then `cat.jpg` 4 deep (208/400), `dear.png` 3 deep (190/400), `dear1.jpg` 4 deep (184/400). Trimming at a mid-grey threshold (ink = pixel < 128) fixes 13 of the 14; `dear1.jpg` still shows 2 blank lines, which is the residual this requirement accepts. The threshold matters and is not free to choose: at a near-white threshold (< 245) JPEG ringing and off-white backgrounds count as ink, so almost nothing is trimmed and 4 of 14 still violate — worse than the mid-grey choice on the same corpus. CON-013 (silhouettes, not photographs) is what makes a mid-grey threshold defensible.
- DECISION REQUIRED alongside the trim: whether FR-021/CON-012's ">2x aspect mismatch" refusal judges the ORIGINAL source extent or the TRIMMED one (CON, technical). Source: analysis of the trim request against merged CARD-026, 2026-09-01. Trimming changes the ratio the guard measures — `cat.jpg` goes 580x580 (1.00) to 330x462 (0.71), `dear1.jpg` 450x450 (1.00) to 287x425 (0.68) — so a tall thin subject centred on a square canvas could be accepted untrimmed and refused trimmed. Swept over all 14 pictures at 20x20: zero verdict flips today, so the corpus does not force the choice and the decision must be made on meaning, not on evidence. Judging the trimmed extent is the more useful reading (white margin is not "the user's picture", which is what CON-012 protects) but it amends CON-012's subject and re-touches EC-007's "before any cropping" clause, corrected only days earlier — the guard would then run after the trim, and the trim needs the decoded pixels.

- AMENDS ADR-0016's export filename convention: the PDF filename becomes `<name>-<WxH>-<difficulty>.pdf`, adding the grid extent between the name and the tier (ADR revision, technical). Source: user request, 2026-09-01. The `-<difficulty>` half already exists and is unchanged; only the extent is new. - AMENDS ADR-0006's closed dependency baseline: a small Unicode TTF ships as package data so a non-ASCII puzzle name renders in the PDF header (ADR revision, technical). Source: user decision, 2026-09-01, resolving the backlog item "Decision needed: a non-ASCII `--name` renders as `.notdef` tofu boxes in the PDF header" (raised by CARD-011/CARD-014, 2026-08-29). Re-verified 2026-09-01 against Pillow's bundled default font: `к`, `о`, `т` and `é` each render a bitmap identical to an unassigned codepoint, while `c` renders — the font is an ASCII-only subset. Filenames are unaffected (sanitization is already Unicode-aware: `кот` passes through verbatim). The option chosen is (a) of the three the backlog item listed, i.e. accept the dependency-baseline exception rather than mangle the name or reject it at the CLI boundary. This is a package-data exception, NOT a new pip dependency: the runtime dependency set stays stdlib + Pillow + NumPy. Urgency is raised by the image-mode naming change above, which turns the user's own filenames into puzzle names automatically and so makes a Cyrillic name the common case rather than an edge case.
