- [ ] **`test_web_upload.py` sweeps the machine-wide temp dir and reds whenever two worktrees run the suite at once.** `_uploaded_temp_files()` globs `nonogram-upload-*` in `tempfile.gettempdir()` and compares the set before and after, so a concurrent worktree's upload fixture counts as this test's leak. - [ ] **Stop asking implementation agents to run the full suite; let the orchestrator's merge gate be the only full run.** Observed in wave 37: every card brief ended with "run the full suite once at the end", and the orchestrator ALSO runs the full suite at the merge gate — so each card pays for two ~17-minute runs, and when two cards are active their suites overlap. Measured at the worst point: **four concurrent pytest processes** on one machine, with a single full run still unfinished after 13 minutes. cmd-start-review's FULL-SUITE LOCK (`meta/kanban/.full-suite.lock`) is orchestrator-side and implementation agents never take it, so nothing serialises them. Fix: brief agents to run only targeted/impact-scoped tests and to hand off on those, and keep the full suite exactly where the definition of done needs it — the per-card merge gate and the per-wave smoke test. Cheaper AND faster feedback, with no loss of coverage (the gate is unchanged).
