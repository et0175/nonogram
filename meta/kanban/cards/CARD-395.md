## What to implement

1. **The marker and its registry.** `wave_close_only` registered in `pyproject.toml`'s `[tool.pytest.ini_options] markers` beside `browser` (declarative, readable by `tomllib` in a test). A plugin module `tests/wave_close_marker.py` (loaded by ONE import line in `tests/conftest.py`, the `hang_guard` pattern, so the hook is testable in a `-p` subprocess) holds a registry: for each file, the marked node-id patterns, the **smoke** node ids the gate keeps in that file, the named **controls** the gate keeps, and the corpus floors (`assert x >= N`) found inside the marked tests, recorded as a table the floor test re-derives with `ast`. A `pytest_collection_modifyitems(tryfirst=True)` hook adds `pytest.mark.wave_close_only` to matching items and NEVER removes, skips or reorders an item. A bare `pytest` (no `-m`) therefore collects and runs exactly what it ran before.
2. **List 1 is marked** (the table above), with the per-file keep list: geometry keeps `..._two_up_pages` (9.5 s) and `test_a_page_box_one_pixel_off_the_trim_reds_the_trim_assertion`; the interior property keeps `..._ParityCountsFromTheTitlePage` and every `TestParity_/TestPlacementBound_...` control; pairing keeps its two cheap tests; kill matrix keeps the 74 tests that are not the two reproductions (every `test_ac1..ac6, g1..g5` control); fixture-scope keeps `EveryTestPassesAlone` and `AFailureDoesNotCascade`; interior_cover keeps the arms' one-case-each counterparts. The author derives the exact node ids from the collected tree and the durations, not from this table. **The public-player family is NOT marked (owner 2026-11-07, CARD-R):** those files are retiring, not slow. List 2 (a handful of admin solver browser sweeps, about 40 to 100 s) ships as an empty second registry block, filled only on the owner's yes in an edit of the registry alone.
3. **The gate states and lifts** (`scripts/impact_set.py`). The `--gate` block gains: the gate COMMAND(S) to run (command 1: `pytest -m "not wave_close_only" [selection files]`; command 2, only when non-empty: `pytest -m wave_close_only <lifted files>`), the count deselected BY THE MARKER derived by a real `--collect-only -m wave_close_only` (never carried), the list of marked FILES lifted and why, and the closing sentence qualified: "nothing more is owed AT THIS GATE; N marked tests are owed at the wave close". The unqualified sentence `then nothing more is owed` must not appear when the deselected count is above zero. Exit codes stay 0/10/11/12 with the same meanings; the plain mode (stdout `FULL` or paths, exit 0) is unchanged. `count` stays injectable with the one-argument callable the CARD-286 tests pass; the marker count is a second optional injectable.
   **The lift rule (exact).** A marked file is LIFTED (its marked tests run at this gate) iff either:
   * **(S) subject edge**: the file is in the subject set of the changed paths: the file itself changed; or a `src/` module it imports (transitively through the existing import graph) or a `tests/` helper it imports changed; or a changed asset/script/data file is NAMED by it or reached through the existing declared-selector / referencer chain. The subject set is computed by the SAME corpus calls `_derive_one` / `_derive_asset` make, MINUS exactly these blanket additions: the always-on scanners, the `tree_readers(...)` walk, `corpus.executors()` for `BROWSER_SURFACE_MODULES`, the "cheap safe rule" `executors() | conftest_users()` for admin statics and templates, and `conftest_users()` via the conftest source closure. (Those blanket rules answer "I cannot see who reads this, so run the browser tests"; they say nothing about a heavy sweep's subject.)
   * **(A) unmodelled blast radius**: any FULL reason whose rule is `unanalysable`, `conftest` or `conftest-closure` (a change to conftest, the pytest config, the Makefile or the selector itself). Then every marked file is lifted: the gate is a bare `pytest`, as today.
   Other FULL reasons (`no-importer`, `no-reader`, `outside-known-roots`, `migrations`, `unknown-asset-type`, `count-unavailable`) lift by (S) alone: a path no test imports, names or reads cannot be a heavy sweep's subject by the derivation's own definition. On `count-unavailable` (exit 11) the gate runs bare: a gate nobody could size is not narrowed.
   **Failure mode, stated in the docstring and the block:** a coupling the derivation cannot see (a path built from pieces, a Jinja include through a helper, a JSON field name) is invisible to (S), so the marked test is deselected, the card merges, and the red appears at the wave close attributed to the wave, not the card. The cost is a bisect over the wave's merges with ONE failing file (`make test-marked`), minutes, not an hour. This is the owner's accepted backstop.
4. **Makefile.** `test` stays the bare full suite and its comment says so. New: `test-gate` (runs `impact_set.py --gate --against $(BASE)` and then its printed command(s), exit code propagated), `test-marked` (`pytest -m wave_close_only`, for a bisect or a pre-wave-close check), `test-wave-close` (bare `$(PY) -m pytest`, prints "WAVE CLOSE: full suite, no marker deselection", and refuses to run if `-m` or `MARKEXPR`-style narrowing is passed through `PYTEST_ADDOPTS`). `test-impact` (the review-cycle gate) is UNCHANGED: a cycle runs the files it selects whole.
5. **The wave-close definition, repo-owned.** `meta/kanban/config.yml` `review.test_command` stays bare and gains a comment naming `wave_close_only` as the reason it must never carry `-m`; a new `review.gate_test_command: "make test-gate"` is the merge-gate form the orchestrator briefs (the skill does not read it; it is the repo's statement, and the existing dispatcher practice of typing the gate in the brief now has one source). `CLAUDE.md` Commands gains three lines (gate form, `test-marked`, wave close). The dispatcher-state `smoke_test: SATISFIED by the last merge gate` convention is retired for waves after this card: a gate that deselected the marker cannot satisfy the smoke test, and the card says so in `Worktree notes` for the orchestrator to carry into the next wave-open (this card does NOT edit `dispatcher.state`).
6. **The fresh duration artefact (precedent CARD-220).** One SOLO, GREEN, armed `--durations=0 --durations-min=0` run committed as `meta/profiling/suite-durations-<date>.txt` with the header `test_suite_profile` requires (commit, host, python, command, wall clock, result, `solo run: yes`), its `suite-hotspots-<date>.md` generated from `rank_durations.py`, and `rank_durations.py` taught one new row in the deciding table: the `wave_close_only` share (marked seconds / attributed seconds), derived from the registry, not typed. ## Guardrails

* **G-1** The marker never changes what a bare `pytest` collects or runs. The wave close and every local full run are bare.
* **G-2** No corpus floor lowered, no test deleted, renamed, skipped or merged (G-4 of the board). Only WHEN a marked test runs moves.
* **G-3** Controls stay at the gate: any test whose only job is to fail on a planted defect (every `test_a_..._reds_...`, `..._is_the_control`, `..._caught`, the cheap negative cases beside a sweep) is on the keep list. A mutant-arm family keeps one arm named in the registry.
* **G-4** The lift rule only ever ADDS marked tests to a gate; no code path may remove an unmarked test from a gate.
* **G-5** No marker decorators in the marked test files (collision with CARD-390 / CARD-392 and with CARD-387's conversions); a rename in a marked file is followed by the registry in the same commit, and AC-2 enforces it.
* **G-6** `dispatcher.state` and the forge plugin are not edited; the orchestrator carries the retired "smoke test satisfied by the last merge gate" convention.
