## Why

Six tests in `tests/test_sourcing_image.py` have been failing long enough to
read as furniture. They were described in this project's own notes — by me,
more than once — as "the `pictures/` corpus failures, they need the owner's
untracked folder on disk". **That was wrong.** `pictures/` has 25 files in it
and the failures are not `FileNotFoundError`; they are assertion failures, and
they are about `tests/fixtures/`, which is tracked.

The fixtures do not match what the tests say they contain:

| fixture | the test's own docstring | what the file holds |
|---|---|---|
| `bands.png` | "the middle third is a flat **128 grey**" | only 0 and 255 — **no grey at all** |
| `landscape.png` | "a black sixth │ white with a **black core** │ a black sixth" (vertical) | three **horizontal** bands, no core |
| `portrait.png` | the same, transposed | the same horizontal bands |

A test asserting that a mid-grey band dithers to ~50% fill cannot pass against
an image with no mid-grey in it. The assertion is right; the fixture is wrong.

### How they got that way

`git log --follow` gives `landscape.png` exactly one commit —
`02a25a2` (2026-09-10), *"feat: create missing image fixtures for sourcing
tests"* — preceded by two attempts at `bands.png` the same day (`2aece6a`
"add missing bands.png test fixture", `4295166` "recreate bands.png fixture
with proper band structure").

So the tests were written first, against images that were never committed, and
the stand-ins were fabricated days later by reading the test names rather than
the assertions. `tests/e2e/README.md` still documents `landscape.png` as
**2000×1000px** — a file that has never existed in this repository.

This is the same defect CARD-070 fixed for `tests/test_nudge.py`, from the same
week and the same cause. CARD-070 re-pinned the tests onto a fixture that
existed; this card fixes the other half — fixtures that exist but are not what
they claim.

### Why regenerate rather than re-pin

The three failing dithering/crop tests state *precise, well-chosen* properties:
a flat mid-grey is the only thing that distinguishes error diffusion from
thresholding, and outer bands plus a centred core is the only shape that tells
a centred crop from a stretch **and** from letterboxing. Those assertions are
worth keeping. It is the images that need to exist.

To stop this recurring, the fixtures are generated by a committed script rather
than fabricated by hand. `02a25a2` produced images nobody could check against
intent because the intent lived only in the test docstrings; a generator puts
the structure in one readable place and makes it re-derivable.

## Guardrails

- **G-1** — **`pictures/` and `pic1/` are not touched.** They are the owner's
  own trial images, their layout is undecided, and nothing in this card needs
  them. The failures were never about that folder.
- **G-2** — the six failing tests' *assertions* are not weakened to fit the
  images. The whole defect is that the images were made to fit the names
  instead of the assertions; repeating that in the other direction would hide
  it. Only `test_a_real_image_that_converts_ambiguously_reports_it` changes,
  and only its pinned source and extent, per the procedure its docstring
  already prescribes.
- **G-3** — the real photographic fixtures (`owl1.png`, `duck1.png`, and the
  rest) are not regenerated, replaced, or re-encoded. They are real pictures
  and several tests pin measured properties of them.
- **G-4** — no production code changes. This card is about test data.

the pin moves to a real photograph, which is what the test's name asks for
anyway.

## Worktree notes

**The six failures had been mislabelled, by me, repeatedly.** They were
reported through this session as "the `pictures/` corpus failures — they need
the owner's untracked folder on disk". `pictures/` has 25 files in it, and not
one of the six raises `FileNotFoundError`: all six are assertion failures
against `tests/fixtures/`, which is tracked. The label survived because six
failures that never change look like furniture, and nobody re-read them. It
took looking at the actual assertion text to see that
`test_the_mid_tone_band_comes_out_dithered_rather_than_thresholded` was failing
because `bands.png` contains no mid-tone.

**Five of the six were fixed by making the images what they were documented to
be**, with no test edited — the assertions were right all along.

**The sixth needed re-pinning, by the procedure its own docstring prescribes.**
`test_a_real_image_that_converts_ambiguously_reports_it` requires a conversion
that stays ambiguous through all five nudges, and the regenerated
`landscape.png` abandons at **no** size in 10..25: a solid rectangle on white
is the most uniqueness-friendly shape there is, and AC-1's "all ink inside the
central block" makes it unavoidable. Those two requirements are in genuine
tension on one fixture, which is why the pin moved to a real photograph —
`duck1.png`, which abandons at every size in 20..25, so the pin does not
balance on one extent. The docstring's lineage list gains the entry rather than
losing its history.

**`tests/e2e/README.md` described `landscape.png` as 2000x1000px.** `git log
--follow` gives that file exactly one commit — the 2026-09-10 fabrication — so
the photograph it describes has never existed in this repository. Corrected
rather than deleted, because the wrong number is the evidence for how the
fixtures drifted.

**Why a generator rather than three more hand-made PNGs.** `02a25a2` fabricated
these by reading the test *names*; the structure the assertions actually need
lived only in docstrings, where no image could be checked against it. It lives
in `make_fixtures.py` now, each choice naming the assertion it serves, and
`test_the_committed_fixtures_are_what_the_generator_produces` fails if the
bytes and the generator ever part company — which is the drift that caused all
of this, made mechanical.

**A flake I caused myself, not a regression.** Two full-suite runs briefly
reported failures in `tests/test_web_server.py::TestWebServer_BindsLoopbackOnlyByDefault`
— they bind real sockets, and I had two suite runs going concurrently competing
for the same ports. Both files pass in isolation on this branch *and* on
unmodified `main`; worth recording so the next reader does not chase it.
