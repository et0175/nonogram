Project Vision

A small CLI tool (with optional local web UI) that generates nonogram puzzles—either from random/idea sources or from user-uploaded images—at a chosen difficulty level, and guarantees each puzzle has exactly one logical solution.

Primary Actor

Puzzle Creator — the developer/user running the CLI or web UI. Generates, tunes, and exports puzzles for personal solving, printing, or sharing the output files with others.

Non-Goals & Out of Scope

  • Multiplayer, user accounts, or persistence beyond local file export
  • Color or multi-value nonograms (classic black/white only)
  • Interactive/playable puzzle output in v1 (static exports only: PNG/SVG/JSON/CSV/PDF)
  • Web deployment or network exposure (localhost-only in web UI, no authentication needed)

Architecture Overview

Layered pipeline, one bounded context (CTX-001), one dependency direction:

cli.py COMP-001 (argparse adapter — parsing only)
orchestrator.py COMP-002 (drives Puzzle aggregate)
sourcing/ COMP-003 (sources a solution grid)
clues.py COMP-004 (run-length encoding)
solver/ COMP-005 (constraint-propagation solver)
difficulty.py COMP-006 (heuristic difficulty scoring)
export/ COMP-007 (PNG/SVG/JSON/CSV/PDF rendering)
web/ COMP-008 (local HTTP server)

Dependency flows inward only: CLI → Orchestrator → Capabilities → Shared errors. Lateral imports are forbidden by structural tests.

Non-Functional Requirements & Constraints

NFR-001: Performance
Non-Functional
Puzzle generation (including regenerate-on-failure loops) should complete within a few seconds for typical sizes up to 20×20 on standard hardware.
NFR-002: Resilience
Non-Functional
Regenerate-on-failure loops must have maximum retry bounds (20 attempts) to avoid infinite loops on infeasible requests.
NFR-003: Correctness (Critical)
Non-Functional
The uniqueness check must never produce false positives. Verified by independent property tests against a brute-force oracle.
NFR-004: Security (Web UI)
Non-Functional
Web server binds to 127.0.0.1 only and refuses cross-site requests via header validation (Sec-Fetch-Site, Origin).
NFR-005: Usability (Print)
Non-Functional
Printed cell size is comfortable to mark (≥6.5mm). Page orientation follows grid shape (landscape for wide, portrait for tall/square).
NFR-006: Usability (Print)
Non-Functional
Page orientation optimizes for grid shape: landscape for wide grids, portrait for tall/square grids.
NFR-007: Export Round-trip
Non-Functional
JSON and CSV exports preserve 100% of puzzle information for exact reconstruction without data loss.

Key Constraints

CON-006: Dependency Baseline
Constraint
No new third-party runtime dependencies. Stack: Python 3.14+ stdlib + Pillow + NumPy only. PDF export uses Pillow's built-in writer.
CON-011: Grid Size Range
Constraint
Each dimension (width and height) must be 10..30 inclusive. MAX_SIZE = 30 applies to all source modes.
CON-013: Image Scope
Constraint
Image sourcing targets high-contrast black/white silhouettes only, not photographs.

Testing Strategy

Testing approach: Unit tests verify individual functions; integration tests verify full pipelines and round-trip exports; property tests verify solver correctness across randomized inputs; UI tests verify web interface and CLI argument parsing.

Acceptance Criteria Overview

Each functional requirement has detailed acceptance criteria in meta/architecture/requirements.yml. Below is the high-level summary of what gets tested and validated for each feature area.

Grid Generation Acceptance Criteria

  • Random grids generate at specified sizes (10..30 per side)
  • Built-in library has 4+ templates with proper key mapping
  • User images load, dither, and convert to pure black/white
  • Density parameter affects filled cell percentage
  • Rectangular grids are supported (NxM notation)

Solver & Uniqueness Acceptance Criteria

  • Solver correctly identifies unique solutions (count = 1)
  • Impossible puzzles (count = 0) are rejected
  • Ambiguous puzzles (count ≥ 2) are detected early
  • No false positives across 100+ test cases
  • Regeneration loops bound at 20 max attempts

Difficulty Scoring Acceptance Criteria

  • Three tiers defined: Easy, Medium, Hard
  • Scores combine propagation depth, backtracking, solver time, puzzle size
  • Resample loops respect tier thresholds
  • Tier is recorded in exports and PDF headers

Export Acceptance Criteria

  • PNG and SVG render grid + clues with correct layout
  • Cell size scales with grid dimension (legible print)
  • JSON exports include width, height, clues, solution, metadata
  • CSV is tabular and spreadsheet-readable
  • PDF contains 2 pages (puzzle + answer key) with name and tier
  • All formats round-trip without data loss

Web UI Acceptance Criteria

  • Form captures source, size, difficulty, name, export formats
  • Web UI and CLI use identical orchestrator pipeline
  • Success/failure reported with file paths on success
  • Server binds to 127.0.0.1 only
  • Cross-origin requests are refused

Image Processing Acceptance Criteria

  • Images trimmed to ink bounding box before fitting
  • Silhouettes fitted to requested grid shape (not square-cropped)
  • Requests with >2:1 aspect mismatch are refused with helpful error
  • Bare --size N derives shorter side from source shape
  • Explicit --size NxM fixes both dimensions
