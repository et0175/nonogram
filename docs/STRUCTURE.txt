DOCUMENTATION MAINTENANCE
═════════════════════════════════════════════════════════════════════════════

When adding docs:
  1. Choose appropriate directory based on content type
  2. Use clear, descriptive names (lowercase-with-dashes.md)
  3. Add overview/purpose section
  4. Link to related documentation
  5. Update relevant README.md
  6. Update INDEX.md if needed

For reports:
  - Date-based naming: YYYY-MM-DD_report_type.md
  - Archive reports older than 3 months
  - Keep latest 10 reports of each type
  - Organize by date and type

Organization Philosophy:
  - Flat structure when possible (avoid deep nesting)
  - Clear semantic organization (by type/purpose)
  - Self-documenting directory names
  - README in each major directory
  - Cross-links between related docs
  - Central INDEX.md for overview
