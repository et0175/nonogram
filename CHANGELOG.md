# Changelog

## 2026-10-28
- CARD-284 (feature): Scanning a printed book's QR code now lands somewhere — `/b/<slug>` heads with the book's own display title, lists its puzzles in book order and taps through to the player, an unknown slug lands softly with a way out, and `/library` filters by tier and size. Static files only: no framework, no build step, no server-side write. Two things are worth recording beyond the feature. The page may now carry **the book's title** — an exemption to the rule that the served site leaks nothing, amended deliberately with the owner's decision and with its residual **declared rather than filtered away**: it is bounded in *where* a title may appear, not in *what* a title may carry, and EC-048 is therefore **not closed and not claimed closed**. And the guard that enforces it was, for one cycle, passing only because a test fixture's book title happened to be innocuous — a control that could not fail, found by mutating it rather than by reading it.
- CARD-305 (feature): A book's four divider pages — one per named level, plus the one before the answer key — become a choice on Print setup instead of being unconditional. The owner asked for an option to **add** them; they were already there in every book this generator has ever written, so what shipped is a **switch, default ON**, and a book with nothing stored prints exactly what it printed before. Turning them off removes one page per named level plus one, and the page count, the walk, the table of contents and the KDP estimate all follow the same figure rather than each deriving their own — the generator's own check raises if the walk and the declared count ever disagree, in both directions. `None` never means off anywhere in the chain: not in the column, not in `PrintSpec`, not in `create_spec`, not in the route, so a form submission that does not carry the control at all leaves a stored choice untouched rather than silently clearing it. Its merge gate was red first, on a migration test unrelated to the feature: that test pinned the schema to an old revision and then read through the ORM, which always describes the newest schema, so adding a column broke it — for the second time in this repository's history. The read is core SQL now, which cannot break that way again, and the one assertion the fix displaced — a stored NULL must read back as "no override was ever given" — was the only one of its kind in the suite and moved to a test of its own rather than being dropped.
- CARD-267 (feature): The player tints the row and the column of the cell under the pointer, and their clue boxes with them, so the gaze does not slide onto a neighbouring line on a big board. It is rendering and nothing else — one class on elements already on the page, no board state, no ARIA, no request per hover, and `solver_state.js` untouched, which is checked structurally rather than asserted. The crosshair reaches the manual editor too (owner decision at review cycle 1), and on a board wide enough for duplicate clue gutters both twins of each clue light. Two boundaries are declared rather than claimed away: the clear fires on leaving `.player-stage`, which is a wider region than the board, so the gutter-corner case is commented and untested; and one mutant survives by being provably dead code. The card also amended its own guardrail — G-6 demanded that the existing player test files run unedited, and that is unsatisfiable by **any** card adding a file to the family, because the page-isolation registry asserts over a glob that includes the file holding it. It now permits edits that are non-weakening and recorded; three exist here, each still killing its own mutant.

## 2026-10-15
- CARD-235 (tech-debt): The browser tests no longer pay socketserver's 0.5 s poll interval on every teardown — the family's share of the suite falls from 39.78% to 29.78% and its teardown from 137.97 s to 11.62 s, from a one-line poll_interval kwarg, with a guard that fails if the interval ever stops being applied.
- CARD-234 (bug): The generated book cover's title now letters from the packaged face the interior uses, at the size the code asks for — fixing a macOS-only font path whose silent fallback printed the title at roughly a seventh of its intended size on every cover generated on the deployed panel.
- CARD-237 (tech-debt): The book-export memory tripwire now bounds the export's own marginal cost against a floor measured on every run, instead of the capped child's total resident set — removing a guard that had drifted onto its own threshold as CPython grew and was failing roughly three full suites in four.
- CARD-217 (chore): The test suite now has a profile of itself, and it answered a question that had been guessed at for five waves. Running the whole suite had roughly doubled in cost per test, and the two standing explanations — the tests that render whole books, or the large generated puzzle corpora — are both wrong. The cost is the browser: the twelve files that drive a real Chromium to test the puzzle player are 39.78% of the total time, where everything else together is 60%. A browser test takes 868 ms; every other test takes 83 ms. The rest of the suite has barely slowed down at all since the figure people were comparing against. Nothing was changed or deleted to find this out — the card adds a recorded measurement, a script that derives every number in the conclusion from it, and instructions for repeating it. Four pieces of planned clean-up work were re-aimed on the result, one of them dropped: retiring duplicated tests would save nothing, because 6057 of the suite's tests finish in under a tenth of a second and hold 7% of the time between them.
- CARD-221 (fix): A book's printed layout no longer depends on which computer made it. The interior's text was set in a font looked up on the machine — present on the Mac, absent on the server the admin panel runs on — while the space reserved for page numbers came from the font that ships inside the app. The two disagreed, and the consequence was not cosmetic: the same book could come out 150 pages on one machine and 151 on the other, which puts it in a different Amazon page band and changes the gutter margin printed into the spine. Every interior face now comes from the packaged font, so the same book is the same book anywhere. Two visible consequences came with it, both decided by the owner: the packaged font is about a tenth wider, so the "How to Solve" page lost the three sentences explaining Easy / Medium / Hard — and the box around them, which would have been a frame around three bare words — while keeping both technique notes and all four worked-example steps; and the gaps between table-of-contents groups shrank from 8.5 to 8.0 pt, which is the same rule the owner chose before, re-measured in the font the book is actually printed in. One accepted limit: at the very smallest trim the app allows, the second guide page loses its page number — a page that already could not print at that size.

## 2026-10-14
- CARD-212 (feature): In the puzzle player, a large board now repeats its clues on both sides of each axis — row clues to the left and the right, column clues above and below — so a player scrolled to the far edge of a big grid still has clues in view. A board gets the second set only while the cells it leaves stay at least 24 px across; below that it keeps the single set it has today, and on a phone it falls back to the mirrored row clues it already used. Small boards are unchanged at every window size. Two older faults turned up and were fixed with it: a clue circle in a right-hand gutter was being drawn over the board's heavy frame (the phone's mirrored clues have done that since they shipped), and a hint's highlight vanished whenever the board redrew — on a phone, every time the URL bar collapsed — while the hint counter went on counting it. One measured improvement that has nothing to do with clues: the board used to be drawn up to four times to decide its layout, about 0.8 s before a big puzzle became usable on an ordinary laptop; it is now drawn once in that case.
- CARD-205 (feature): The book's table of contents no longer lists every puzzle by name. It is now a short, structural list — "How to Solve Nonograms", then each level that has puzzles as a heading with a "Puzzles 1–60" row under it, then "Solutions" — with leader dots running from each label to its page number. A 150-puzzle book's contents went from 150 rows across four pages to eight rows on one, which makes the whole interior three pages shorter (310 → 307). That shorter book falls in a different KDP page band, so the page count Amazon is quoted for the printed gutter margin and the page count the export actually writes are now cross-checked at every place the book derives them — including one that nothing had been checking, where a 150-puzzle book would have been quoted 310 pages for a 307-page book. One measured limit, owner-decided: the gaps that set the level groups apart are 8.5 pt rather than a full blank line, because on the shortest trim the profile allows, four full-line gaps pushed the contents page's own page number off the sheet.
- CARD-211 (feature): In the puzzle player, Region is no longer buried in the brush dropdown — it is its own on/off button next to it, and the dropdown now holds just the four brushes (Black, White, Maybe, Undecided). Two behaviour changes came with it: **picking a brush no longer switches Region off**, so you can arm Region, change your mind about the brush, and still drag (under CARD-194 that silently disarmed it, which made sense only while Region lived inside the same menu); and the brush button no longer changes width with the brush name, so the Region button stays put instead of sliding about 40 px sideways right before you reach for it. Everything else about Region is unchanged: it arms the next drag with the current brush on any pointer type and switches itself off once that drag is done.
- CARD-204 (feature): Book puzzle pages no longer centre their grid — it now sits flush to the page's outer edge, mirrored by parity (right on right-hand pages, left on left-hand ones), and each puzzle page carries a 2x2cm QR-code slot. The QR is deliberately a visibly-fake placeholder for now: there is no public solver to point it at yet, so a scannable code waits on that (CARD-210). Every two-up page also keeps its page number, which it had been losing whenever the lower puzzle sat flush against the margin. Caught and fixed before merge: the new flush edge made an over-wide answer-page caption overhang the trim margin entirely (a long picture name put ink 9.6mm outside the page, clipped off the sheet), and the fix for that then let a clamped caption print on top of the page number on packed answer pages — both now bounded and tested. One accepted cost, measured and owner-approved: the folio reserve refuses about 5% of puzzle pairs that would otherwise share a page, so books run very slightly longer.
- CARD-214 (feature): Single-puzzle generation can now be asked to make a picture uniquely solvable by REVEALING a few of its cells instead of changing the picture. Until now a picture whose clues had several solutions was either mutated (random grids get a cell-pair repair, uploaded images get a pixel nudge) or refused outright — and for a real picture the common outcome was a refusal. With the new option, when a mode's own recovery has run out, the generator reveals the fewest cells it can — the first ambiguous cell each time, deterministically, capped at 5% of the grid — and the puzzle ships with those cells given. The grid and its clues are never touched. The solver learned the matching question ("how many solutions are there given that these cells are known?"), and the project's one mandatory correctness property — never report a puzzle unique when it is not — was re-established for it against an independent brute-force checker that shares no code with the solver. Caught during review: a policy branch that refuses a revealed puzzle whose difficulty misses the requested tier was unverified, because the test named for that behaviour never actually reached it. Nothing renders or stores the given cells yet (CARD-215 and CARD-216).
