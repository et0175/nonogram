test(CARD-318): spy on the hand-off, because the store's fallback was hiding both batch call sites

Two mutants survived the first run and both said the same thing: replacing
`strategies_used=list(puzzle.strategies)` with `[]` — in the random batch
generator (M6) and in the image route (M9) — left an all-rows assertion
green. `add_puzzle` derives the list whenever its caller hands it an empty
one, so the store's safety net makes a generator that passes nothing
indistinguishable from one that passes the real list, read from the row.

AC-139 says "that puzzle's **real** list", so the value the generator hands
over is what has to be observed. Both tests now spy on `add_puzzle` as well
as reading the row back, and both mutants red.

Also corrects a false claim this card would otherwise have shipped. The
AC-140 order test's docstring said it caught a sorting renderer; mutant M4
shows it does not — `sorted(reversed(STRATEGIES))` is `reversed(STRATEGIES)`
for that fixture, so the sorting mutant is caught by the test above it
instead. The docstring now records the measurement rather than the
assumption, which is the same defect class as the dead refs themselves.
